## 2. 남은 작업

### 2-1. 수동 검증 (최우선)

브라우저 e2e를 쓸 수 없어(아래 "도입하지 않기로 한 것" 참고) 로그인 후 동작은 사람이 확인해야 한다. 개발 서버(`yarn dev`)에서 구글 로그인 후 진행한다.

**클라이언트 전환(2026-09) 분**: 페이지 전체 리로드 없이 동작하는지 본다.
- [ ] 학생 등록: 검증 실패 시 입력값 유지 + 필드 오류 표시, 성공 시 토스트 + 폼 초기화
- [ ] 학생 수정·삭제: 삭제 후 목록으로 이동 + 토스트
- [ ] 교사 수정: 일반 교사는 활성 상태 체크박스가 비활성인지, 저장 후 값이 유지되는지
- [ ] 가입 관리 승인·거절: 대기 목록에서 빠지고 처리 목록에 추가되는지
- [ ] 가입 관리 권한 토글·삭제: 본인 계정은 차단되는지
- [ ] 대시보드 주간 일정 새로고침
- [ ] 일반 교사 계정으로 `/api/signup-management`, `/api/students/talent-reset`을 직접 호출하면 403인지

**전수조사(2026-10) 분**:
- [ ] 승인 대기 계정을 승인한 뒤 5분 안에 재로그인 없이 `/pending` → 홈으로 넘어가는지
- [ ] 교사를 거절·삭제한 뒤 5분 안에 해당 계정이 학생 관리 등 페이지에서 차단되는지
- [ ] 출석 토글·달란트 조정, 탭 전환, 출석부 모달이 이전과 같은지
- [ ] 대시보드 수치(금주 출석 수, 13주 추이, 분기 생일, 교사 생일)가 배포 전 화면과 같은지
- [ ] 브라우저 개발자 도구에서 세션 쿠키가 5분마다 재발급되는지(`__Secure-next-auth.session-token`의 Set-Cookie)

### 2-2. 운영 판단이 필요한 것

| 항목 | 현재 동작 | 선택지 |
|---|---|---|
| 교사 `isActive`(비활성) | 교사 목록의 분류에만 쓰이고 접근을 막지 않음 | 그대로 둠 / proxy·가드에서 비활성 교사 차단 |
| 달란트 초기화 후 출석 취소 | 초기화가 `ATTENDANCE` 로그까지 지워서, 같은 주에 출석을 취소하면 달란트가 -1이 됨 | 그대로 둠 / 0 미만 방지 / 초기화 시 금주 출석 로그 보존 |
| 졸업생의 출석 명단 포함 | 출석 관리 '전체' 탭에 졸업생도 보임(학생 관리에서만 분리됨) | 그대로 둠 / 출석 명단에서 제외 |
| 학생 등록·수정 화면 | 폼은 클라이언트화됐지만 여전히 별도 페이지로 이동 | 그대로 둠 / 모달로 전환(사용해보고 판단) |

## 3. 도입하지 않기로 한 것 (재검토 조건 포함)

- **Playwright(e2e)**: 근거는 세 가지다.
  - CI가 없어 자동으로 돌릴 경로가 없다.
  - 가장 검증하고 싶은 구글 OAuth 로그인은 Google이 자동화 브라우저를 차단한다.
  - 인증 가드는 `proxy.ts` 단위 테스트가 더 싸게 커버한다.
  - 재검토 조건: CI를 붙이거나 인증 e2e가 필요해질 때. 이때는 `AUTH_SECRET`으로 JWT 쿠키를 직접 발급해 주입하는 방식으로 확장한다.
- **`react-error-boundary`**: 라우트 단위는 Next.js `error.tsx`/`global-error.tsx`로 처리한다. 위젯 단위(단일 카드 등) 격리가 실제로 필요해질 때 재검토한다.
- **Storybook**: CSS 변수(`--color-*`) + `btn-*` 클래스 + `getButtonClassName()`으로 재사용이 충분하고, 1인 운영 규모에서는 유지 비용이 더 크다.
- **전역 상태 라이브러리(Zustand)**: 여러 페이지가 함께 참조하는 클라이언트 상태가 없어 제거했다. 그런 상태가 생기면 재검토한다.

## 4. 작업 시 알아둘 것

- **Node.js 20.9 이상**이 필요하다(Next.js 16). Node 18에서는 `yarn test`가 `ERR_REQUIRE_ESM`으로 시작조차 안 된다. 새 PC에서 `tsc`가 `.svg` import를 못 찾으면 gitignore 대상인 `next-env.d.ts`가 없는 것이므로 `yarn next typegen`(또는 `yarn dev` 한 번)으로 생성한다.
- 테스트는 `vitest@5` + peer `vite@7`이다. yarn v1은 peer를 자동 설치하지 않는다.
- `.prettierrc`의 `importOrder` 마지막에 `"^node:"` 그룹이 있다. eslint `import/order`와 prettier 정렬이 node 빌트인 위치를 두고 충돌해서 넣은 것이므로 지우지 않는다.
- proxy는 Next.js 16 기본값인 **Node.js 런타임**에서 돌기 때문에 Prisma를 쓸 수 있다. `runtime` 설정은 proxy 파일에서 쓸 수 없다(설정하면 에러).
- 세션 쿠키 재발급은 next-auth v4와 같은 이름·옵션을 쓴다(`src/proxy.ts`의 `isSecureCookie`/`getSessionCookieName`). next-auth를 업그레이드하면 쿠키 규칙이 바뀌었는지 확인할 것.
